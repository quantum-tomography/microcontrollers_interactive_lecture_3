Theoretical Foundations

Address Bus

Unidirectional: Sends the address binary word from the CPU to memory. Determines which specific cell (0x00 to 0x0F) will be accessed.

R/W Control Signal

Single Line Connection:
• R/W = 1 (High): Read Operation
• R/W = 0 (Low): Write Operation

Data Bus

Bidirectional: Transfers the byte of data from memory to CPU (during Read) or CPU to memory (during Write).

Microcontroller Architecture: Von Neumann vs. Harvard Architecture

How memory organization affects memory access, instruction width, and overall execution speed.

Fig. 1.5 & Fig. 1.6

Von Neumann Architecture (Фиг. 1.5)

Shared Bus & Memory
Central Processor
8-bit Bus
Single Highway
Program & Data Memory
  • Unified Memory: Program code (instructions) and data reside in the exact same memory space.
  • Single 8-bit Bus: Instructions and data are fetched sequentially over one shared data bus.
  • Multi-cycle Bottleneck: Instructions larger than 8 bits require 2 or more fetch cycles, reducing overall processing speed.
  • Examples: Intel and Motorola microcontrollers.

Harvard Architecture (Фиг. 1.6)

Separate Buses & Memories
Program Memory
12/14/16 bit
Central Processor
8 bit
Data Memory
  • Physically Separate Memories: Independent Flash Program Memory and Data RAM.
  • Separate Dedicated Buses: CPU can read data and fetch the next instruction simultaneously!
  • Flexible Instruction Width: Instructions can be wider than data (e.g., 12, 14, or 16 bits in PIC microcontrollers).
  • Single-word Fetch: Each instruction is fetched in one binary word, drastically boosting execution speed.
Key Advantage of Harvard Architecture: By decoupling the instruction memory from the data memory, instructions can be fetched in parallel with data access. This eliminated the classic Von Neumann bus bottleneck and paved the way for modern high-speed microcontrollers like the Microchip PIC series.

Instruction Set Paradigms: RISC vs. CISC Microcontrollers

Comparing Reduced Instruction Set Computers (RISC) with Complex Instruction Set Computers (CISC).

Instruction Set Architecture (ISA)

RISC Architecture

Reduced Instruction Set Computer

~35 Instructions
  • Small, Optimized Instruction Set: Works with a reduced number of basic, highly efficient instructions (e.g., 35 instructions in PIC16CXX/PIC16FXXX).
  • Easy to Memorize: Developers only need to master a small set of operational codes.
  • Instruction Decomposition: Complex operations are executed by combining 2 or more basic instructions instead of single complex ones.

CISC Architecture

Complex Instruction Set Computer

100+ Instructions
  • Large, Expanded Instruction Set: Provides over 100 specialized instructions (e.g., Intel, Motorola microcontrollers).
  • Single-Instruction Operations: Complex tasks can often be accomplished in a single opcode instruction.
  • Hardware Complexity: Larger instruction decoding logic inside the CPU hardware.

Common Misconception Debunked: Does RISC Limit Functionality?

A common misconception is that a smaller instruction set limits what a microcontroller can do. This is false! Anything a 100-instruction CISC microcontroller can perform can also be achieved by a 35-instruction RISC microcontroller. The only difference is that operations requiring 1 CISC instruction might take 2 or more instructions on a RISC core.

Performance (Производителност) vs. Execution Speed (Бързодействие)

Although often used interchangeably, these two metrics evaluate different aspects of efficiency.

1. CPU Performance (Производителност)

MIPS Unit

A characteristic specifically of the CPU core. Measured by the number of raw instructions executed per unit time, usually given in MIPS (Million Instructions Per Second). PIC microcontrollers achieve up to 10 MIPS.

2. System Execution Speed (Бързодействие)

Overall System

Evaluates the overall operational capacity of the entire microcontroller system to complete concrete tasks. It depends not only on CPU MIPS, but also on memory access time, architecture type (e.g. Harvard), and peripheral effectiveness.

Rule: High CPU performance (MIPS) does not always guarantee high system execution speed if memory or peripherals create bottleneck stalls.

Microcontroller Peripherals (Периферни устройства)

Peripherals are functional hardware blocks inside the microcontroller that extend its capabilities. While a core MCU could run without them, interacting with the real world would be nearly impossible.

PC Analogy

Just as a Personal Computer needs a monitor and keyboard to communicate with a user, a microcontroller relies on I/O ports and peripherals to interface with external sensors and actuators.
